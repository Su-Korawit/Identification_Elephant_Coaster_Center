# ผลทดลอง: วัดผลแบบกัน leakage (block split) และทดสอบช้างตัวใหม่

ข้อมูล: `Day1_workshop_data_E` ช้าง 3 ตัว (Ai_ko 1,837 / Nam_Fon 1,906 / Rat_sa_mee 2,242 ภาพ รวม 5,985 ภาพ) ชื่อไฟล์ระบุมุม front/back/left/right

## วิธี
- ครอปตัวช้างด้วย YOLO (`yolo11n.pt`) + `enhance_image` เหมือน pipeline ใน repo (ตรวจพบช้างครบทุกภาพ)
- แบ่งต่อ (ช้าง, มุม) ตามเลขเฟรมในชื่อไฟล์: 60% แรก = train, 63-73% = validation, 76-100% = test
  เว้นช่วง 60-63% และ 73-76% เพื่อกันเฟรมติดกันรั่วข้ามชุด (ผลต่างจาก `random_split` เดิมที่สุ่มรวมเฟรมติดกันเข้าทั้งสองชุด)
  ข้อสมมติ: เลขในชื่อไฟล์เรียงตามเวลา (ยืนยันไม่ได้)
- เทรน `ElephantReIDModel` ใหม่ 20 epoch (CrossEntropy, Adam lr=1e-4, batch 32, augmentation จาก `reid_dataset.py`)
- ทำนายด้วย FAISS nearest neighbour จาก embedding ของชุด train
- จำนวน: train 3,596 / val 597 / test 1,430

## ช้างตัวใหม่ (open-set) -- จุดอ่อน
ภาพช้างที่ไม่อยู่ใน 3 ตัวนี้ 9 ภาพ (`Unknown/`) กับโมเดลที่เทรนใหม่:
ที่ threshold 0.2 ถูกปฏิเสธถูกต้อง 3 ภาพ (ระยะ 0.258, 0.529, 0.575) และถูกตอบเป็น Ai_ko ผิด 6 ภาพ (ระยะ 0.002-0.08)
สรุป: ความแม่นยำสูงเฉพาะช้างที่รู้จัก การปฏิเสธช้างตัวใหม่ยังไม่ดี ต้องแก้ต่อ (เช่น เทรนด้วย metric loss ให้ embedding ไม่ยุบเป็นจุดต่อคลาส)
ข้อจำกัด: มีแค่ 9 ภาพ และโมเดลนี้เป็นรุ่นเทรนซ้ำด้วย CrossEntropy ไม่ใช่รุ่นเดิมใน `artifacts/`

## Pilot กับโมเดลเดิมใน `artifacts/` (165 ภาพ ไม่ใช่ชุดทดสอบสะอาด)
ที่กฎของ `infer.py` (`match >= 99%` เทียบเท่า dist <= 0.002) ภาพทั้ง 165 ภาพถูกตอบ Unknown (100%)
ที่ threshold 0.2 ตอบถูก 63%, Unknown 36%, ผิด 1% -- ยืนยันว่า `match_wantted = 99` เข้มเกินไป
